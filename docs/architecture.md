# 架构与数据边界

浏览器 → Vite 开发代理 / Nginx → Spring Boot → MySQL；Redis 提供会话及短期缓存。模块化单体，不使用消息队列或微服务。

业务服务层负责校验与事务，Controller 只路由动作。数据库迁移包含 19 张表。模板检查项及任务快照存储为 JSON，检查结果为 JSON，角色权限为 JSON；其余主数据与关联使用外键、唯一键。

## 权限

| 角色 | 业务写入 | 数据范围 |
| --- | --- | --- |
| ADMIN | 系统配置、业务管理；仍不能自审自验 | 全局 |
| ASSET | 资产登记编辑、领用维修、迁移报废申请、位置分类维护 | 本部门 |
| ENGINEER | 自己的巡检任务、工单处理；故障申报、告警处理 | 本部门，执行动作进一步校验处理人 |
| SUPERVISOR | 巡检配置、工单分派验收、资产审批、规则管理 | 本部门 |
| AUDITOR | 无业务写入 | 本部门审计日志 |

管理员可调整非 ADMIN 角色的功能权限，AUDITOR 仅允许日志读取。接口不信任前端隐藏按钮或请求中的部门字段。通过角色授权不能绕过部门范围和“不能自行验收/审批”的限制。

单企业、不含跨部门调拨。用户变更部门、角色或停用前必须转交资产、未完成任务和工单，并停用关联计划。部门停用前必须停用用户。分类与位置被有效资产使用时不能停用。

## 会话

JWT HS256，签发者 eam-ops，有效期两小时；Redis 保存 session jti。每次请求检查 Redis、用户启用状态、部门状态及数据库 auth_version。退出删除当前会话；修改密码和角色权限提升版本使已有 token 失效。Redis 不可用时认证拒绝访问。密码 BCrypt，无浏览器长期持久化 token，仅 sessionStorage。

## 一致性与并发

- 工单、审批、巡检执行携带 version；影响行数为 0 返回 409。
- 涉及设备故障状态的路径先锁资产，再锁工单或任务；关闭工单时重新判断其他未关闭工单和活动告警。
- 工单事务同时写入状态、流转记录、资产履历、审计和站内通知。没有外部消息副作用。
- 数据缓存失效在事务提交后执行。缓存不可用时统计回源 MySQL；30 秒 TTL 限制旧数据存活期。
- 巡检 `(plan_id, asset_id, cycle_date)` 唯一，生成过程更新 next_run 与任务处于同一事务；每分钟补偿。一次最多 400 周期，未补齐部分下次继续。
- 月度使用原始 anchor_day，如 1 月 31 日 → 2 月末 → 3 月 31 日。
- 活动告警 `active_key` 唯一；确认保留 active_key，恢复设 NULL；再次异常是新事件。
- 通知 dedup_key 唯一，逾期任务和工单不会每分钟重复通知。

## 统计口径

资产与活动告警为当前快照；工单范围按创建时间、巡检范围按 cycle_date，日期两端均包含。故障率为当前故障资产 / 未报废资产，非历史故障频次。平均耗时只包含已关闭工单的创建至关闭时间。无任务时完成率显示 0%。统计授权范围与对应列表一致。

## 已采用的边界

一个用户属于一个部门和一个角色；角色可配置多个权限。计划创建后可启停，变更周期、设备集合或执行人通过停用旧计划并创建新计划完成。已生成任务保留原执行人与模板快照。历史业务不提供物理删除接口。告警恢复不直接将资产标为正常，设备恢复由工单验收确认。
