# 业务演示脚本

先启动 demo profile，使用 `.env` 中的演示密码。所有名称、IP、事件为虚构。

1. 以 `asset` 登录，在“设备资产”登记一台服务器，选择一部机房/机柜及责任人。设备初始为待领用，点击“领用”填写原因。
2. 切换 `supervisor`，创建检查模板，检查项每行一项；建立每日计划，选择刚才的设备和 `模拟·运维工程师1`，开始日期设为今天。点击“生成”，重复点击不会重复任务。
3. 切换 `engineer`，执行任务，将一个检查项设为异常，填写说明并提交；在已完成任务点击“异常转工单”，填写故障信息。
4. 切换 `supervisor`，在工单列表分派给工程师；切换 `engineer` 接单、记录过程、提交验收。
5. 切换 `supervisor`，验收时填写结论、勾选“确认设备故障已恢复”，提交。该资产没有其他活动告警或工单时恢复运行。
6. 打开资产详情查看履历、工单详情查看流转时间线；看板显示新的工单和巡检统计。
7. 以 `asset` 申请迁移，`supervisor` 审批。申请后若资产发生变化则审批返回版本冲突，需重新申请。
8. 以 `supervisor` 在告警中心“模拟指标”上报 CPU=95，多次上报只增加活动告警次数；确认不会恢复，正常指标上报或手动登记恢复后事件结束。
9. 以 `engineer2` 登录，无法查看一部数据；以 `auditor` 登录，只能看到本部门审计日志和个人通知。

`npm run test:e2e` 自动执行上述核心闭环并生成截图；测试会创建带时间戳的验收资产与计划。

初始演示数据包含两个业务部门、32 台资产、两个计划、指标规则、多种状态工单及活动告警。新环境不会包含本次测试期间产生的额外资产。
